# 作品の著作権・翻訳権管理監査

監査日: 2026-11-17
対象: 青空文庫カタログ取得から作品選択、注文スナップショット、PDF生成までのローカル実装

## 確認できた実装

- `app/api/works/route.ts` は青空文庫の拡張CSVから作品名、姓・名、`役割フラグ`、姓読み・名読み、図書カードURL、本文URLを読み込みます。役割が「著者」「作者」「原著者」の人だけを `work.author` に入れ、翻訳者などは `contributors` の役割を保ったまま作品詳細APIへ返します。
- `/create` の詳細表示は著者欄と、翻訳者などの関係者欄を分けています。今回追加した五十音索引も著者役割だけを作家一覧に含めます。
- 作品選択後の `BookWork` は `id/title/author` と青空文庫URLだけを保持します。翻訳者などの役割・権利情報は注文データには引き継がれません。
- `app/api/orders/route.ts` の注文下書き検証は構造・URLなどを確認しますが、作品や翻訳の商用印刷許諾を確認しません。
- 決済可能性、PDF生成キュー、`scripts/render-order-assets-worker.mjs` の本文取得・製本PDF生成にも、権利状態・個別許諾を照合する処理や権利台帳は見当たりません。権利未確認の作品もカタログ上は選択でき、注文・製本データ生成へ進み得る設計です。

## リスク

青空文庫には、保護期間が満了した作品だけでなく、著作権者の同意を得て公開された作品もあります。後者は、青空文庫で閲覧できることだけでは、有償で全文を複製し印刷・販売できる根拠になりません。青空文庫の取扱基準は、保護期間中の作品について私的使用の範囲を越える利用・複製・再配布には権利者の許可が必要とし、図書カード等に明記された特別許諾の範囲での利用を案内しています。

翻訳作品では原著作物と翻訳文の権利を別々に確認する必要があります。原作者の権利が満了していても翻訳者の権利が残る場合があり、現在の注文スナップショットでは翻訳者情報が失われます。印刷物上の適切な翻訳者表示や、許諾条件の履行も確認できません。

日本の一般的な著作権保護期間は著作者の死後70年ですが、2018年12月30日の延長は、その前日時点で権利が消滅していなかった著作物等に適用され、すでに消滅した権利を復活させません。無名・変名・団体名義・共同著作物などの起算規則、外国作品の条約・戦時加算等もあるため、死亡年だけで機械判定するのは危険です。

## 公開前に必要な対応

1. 作品ごとに、原作品と利用する底本・翻訳・校訂等を個別に記録する権利台帳を用意する。最低限、各権利者と役割、状態（未確認／保護期間満了を確認／許諾取得／利用不可）、確認根拠・証拠URLまたは文書、対象地域、許可された利用（有償印刷、販売、電子複製、改変等）、条件、確認日、確認者、再確認日を持たせる。
2. 翻訳者・共同著作者・編者など、関係者ごとに権利状態を別管理する。著作者人格権、出典・底本・青空文庫ファイル由来表示の要件も確認する。
3. まず販売候補を少数に限定して人が根拠資料を確認し、法的判断が曖昧な作品は対象外にする。法務担当または弁護士の確認なしに、死亡年だけから「販売可」を自動付与しない。
4. 台帳と審査手順を整備した後、注文確定または製本ジョブ取得のサーバー側で、すべての対象作品と翻訳等が明示的に承認済みであることをfail-closedで確認する。カタログ表示だけの制御では直接APIや古いドラフトを防げない。
5. 権利データを注文スナップショットへ改ざん不能な形で残し、どの許諾・底本・テキスト版で製造したか監査できるようにする。既存注文を遡って変更するのではなく、導入前に互換性と移行方針を別途レビューする。

この変更では、既存カタログを一括で無効化する権利フィルターやDB変更は実施していません。公開前の法務要件として扱い、販売対象の確定前に解決してください。
