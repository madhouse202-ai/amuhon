# 編む本：UX・印刷データ・権利台帳 引き継ぎ

## 現在の範囲

- `/create` は作品選択中にもPC右側の追従パネル、スマートフォンの展開式下部パネルで作品順・著者・推定本文ページ数を表示します。最終ページ数には目次・出典・奥付等が加わり、価格は最終確認後に確定する案内を表示します。
- 背表紙は作品名・著者名を一列で縮小・省略表示し、作品詳細とアクセシブル名は全文を保持します。
- `/cover` は低解像度の見開き画像で表裏・背表紙を同時にプレビューします。背幅は推定ページ数から表示し、完成時確定と案内します。
- `/final` に青空文庫の出典・底本情報と、権利台帳の許諾条件を掲載する巻末ページを追加しています。
- 一般画面から印刷用PDF・高解像度PNG保存と開発検証操作を除外しました。印刷データのAPIと管理取得は引き続きサーバー認証・非公開Storage・固定パス・ハッシュ照合で保護します。
- 背表紙の長い著者名は1列のまま最小8pxに縮小し、タップ詳細とアクセシブル名では全文を維持します。
- 通常アプリの本番ビルドでは印刷用画面を有効化せず、Dockerレンダラー専用ビルドだけが内部印刷画面を使います。

## 権利台帳と販売ゲート

`20261118000100_work_commercial_rights_ledger.sql` は未適用の追加migrationです。作品のテキスト版とSHA-256、カタログ上の関係者、根拠、確認日・確認者、条件を記録し、関係者ごとにもA/B/C状態と個別の根拠・条件を持たせます。自動seedや死亡年による承認はありません。RLSを有効にし、直接アクセスを拒否、固定search_pathのSECURITY DEFINER RPCだけをservice_roleから利用します。

現在は承認レコードがないため、注文作成・Checkout・生成キューは販売を拒否します。運用前に人が正確なテキスト版ごとに調査・記録し、全関係者がAであることを確認する必要があります。翻訳・翻案・共同著作は関係者を個別に確認してください。

重要な未実装点：注文APIはブラウザー由来の版ハッシュを拒否しますが、信頼できるカタログ行と取得したXHTMLからサーバー側で正規版ハッシュを作る事前処理はまだありません。したがって台帳を登録するだけでは現行の注文フローは通りません。任意URLを読ませる経路を作らず、許可した青空文庫カタログIDからカタログ行を解決し、固定ホスト・redirect拒否・応答サイズ/時間制限付きでXHTMLを取得・ハッシュし、実際の組版本文と同じ版であることを確認するサーバー側事前生成工程が必要です。

Checkoutも権利RPCの応答がオブジェクトである点を誤って真偽値扱いし、`approved:false`を拒否判定できない箇所がありました。RPCの厳密なboolean決定値パーサーへ変更し、拒否時は決済・Checkout RPCへ進まない回帰テストを追加しています。

## 印刷生成・価格の未接続点

Cloud Runの既存キューは決済後の生成を担当します。現在の決済前価格確定は既存のアップロード済みPDF検証を必要とするため、これを無効化してキューだけを残すことはできません。本番の注文作成・アップロード・検証・Checkout APIは`NODE_ENV=production`でfail-closed（503）です。購入者にファイル選択を要求する旧経路は公開時に有効になりません。

次の実装では、選択作品スナップショットからサーバーが本文PDFと低解像度でない印刷表紙を生成・検証し、最終ページ数、価格、背幅、ハッシュを注文確定前に固定してください。決済後キューは同じ入力・版ハッシュ・組版バージョンに対して再生成または検証し、固定済みページ数・価格・背幅と一致しない場合は入稿可能にしてはいけません。生成失敗は保留し、再決済や既存データ上書きを避けます。

## 管理者の手動入稿

`20261118000200_order_printer_confirmation_audit.sql` は未適用です。準備状況RPCは決済、生成成功、ページ数、背幅/保管物、権利Aを確認します。管理者向けファイル取得は認証済み管理者かつ準備完了の場合だけ、非公開Storageから固定パスで返します。入稿状態の変更は行ロックと監査イベントを使い、製本直送.com側で受付確認が済んだ後にのみ注文番号とともに「入稿済み」にできます。発送済みも別途確認が必要です。保留は決済済みなら、生成・権利に問題のある注文も記録可能です。保留解除や処理開始には引き続き準備完了と権利Aが必要です。

## 注文保存エラー

別worktreeには`.env.local`がありませんでした。注文保存APIは少なくとも`SUPABASE_URL`、`SUPABASE_SECRET_KEY`、32文字以上の`ORDER_RATE_LIMIT_SECRET`を必要とします。注文保持日数`ORDER_DRAFT_RETENTION_DAYS`は未設定時に既定値を使います。`SUPABASE_URL`はamuhon-stagingのURLを使い、本番URLを設定しないでください。秘密値を作業環境間でコピーせず、Windows上の承認済みな秘密保管場所からこのworktreeのローカル環境へ手動設定してください。値はログやチャットへ貼らないでください。
